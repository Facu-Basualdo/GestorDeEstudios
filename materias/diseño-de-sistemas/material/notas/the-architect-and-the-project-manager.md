# The Architect and the Project Manager

> El project manager es responsable del desempeño general del proyecto, mientras que el arquitecto de software es responsable de los aspectos técnicos internos, y su relación tiene un gran impacto en el éxito del proyecto.

Una de las relaciones más importantes dentro de un equipo es la que existe entre el arquitecto de software y el project manager. El project manager es responsable del desempeño general del proyecto —típicamente de mantenerlo dentro del presupuesto, en el cronograma y con las personas adecuadas haciendo los trabajos adecuados. Para llevar a cabo estas responsabilidades, el project manager suele recurrir al arquitecto del proyecto en busca de apoyo.

Se puede pensar al project manager como responsable principalmente de los aspectos del proyecto orientados al exterior, y al arquitecto de software como responsable de los aspectos técnicos internos. La vista externa necesita reflejar con precisión la situación interna, y las actividades internas necesitan reflejar las expectativas de los stakeholders externos. El project manager debe conocer y transmitir a la alta dirección el progreso y los riesgos del proyecto; el arquitecto de software debe conocer y transmitir a los desarrolladores las preocupaciones de los stakeholders externos.

La relación entre el project manager y el arquitecto de software puede tener un gran impacto en el éxito del proyecto. Deben tener una buena relación de trabajo y ser conscientes de los roles que ocupan y de los límites de esos roles. El Project Management Body of Knowledge (PMBOK) lista una serie de áreas de conocimiento para los project managers; la Tabla 24.1 identifica el área de conocimiento descrita por el PMBOK y el rol del arquitecto de software en esa área.

**Recomendaciones para el arquitecto:** mantener una buena relación de trabajo con el project manager, ser consciente de las tareas y preocupaciones del project manager y de cómo el arquitecto puede apoyarlas.
