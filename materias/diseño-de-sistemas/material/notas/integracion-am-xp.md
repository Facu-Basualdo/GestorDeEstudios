# Integración de AM con XP (Programación Extrema)

> XP es una metodología de mayor alcance que AM, en la cual las prácticas de AM pueden ser adaptadas; existe una correspondencia filosófica y práctica entre ambos métodos.

XP es una metodología con un alcance mayor que AM, en la cual dichas prácticas pueden ser adaptadas. Más aún, si bien XP incluye el modelado como parte de su proceso no es muy explícito acerca de como debe ser realizado. He aquí una oportunidad para AM. Así mismo, debido a que tanto XP como AM son ambos métodos ágiles, es mucho más sencilla su integración que en el caso de metodologías prescriptivas como RUP. Existen varias apreciaciones incorrectas acerca de XP y el modelado. Las tres principales son que en un proyecto XP no se modela, en un proyecto XP no se documenta, o si se modela, los únicos artefactos disponibles son los de UML. Más allá de la integración existente entre las prácticas AM y XP, existe una correspondencia filosófica entre ambos métodos. La siguiente tabla muestra la aplicación de prácticas AM y prácticas XP:

| Práctica AM | Práctica XP correspondiente |
|---|---|
| Participación activa del Stakeholder | Cliente en el Lugar |
| Aplicar estándares de modelado | Codificación Estándar |
| Aplicar patrones cuidadosamente | YAGNI, diseño simple |
| Aplicar los artefactos correctos | “si lo necesita, hágalo” |
| Propiedad colectiva | Propiedad colectiva (original de XP) |
| Considerar la prueba | Probar antes de codificar |
| Crear varios modelos en paralelo | (adoptar si se desea) |
| Crear contenido simple | Diseño Simple |
| Representar modelos simplemente | (ídem) |
| Descartar modelos temporarios | Viajar Liviano |
| Presentar los modelos públicamente | Comunicación, Comunicación Abierta y Honesta, Propiedad Colectiva |
| Formalizar modelos contractuales | “si lo necesita, hágalo” |
| Iterar hacia otro artefacto | Iterar entre artefactos (código, tarjetas CRC, pruebas) |
| Modelar en pequeños incrementos | Enfoque incremental vs BDUF |
| Modelar para comunicar | Comunicación Abierta y Honesta |
| Modelar para comprender | Uso de tarjetas CRC |
| Modelar con otros | Programación de a pares |
| Probar con código | Experimentos Concretos |
| Reutilizar recursos existentes | (no explícitamente excluido) |
| Actualizar solo cuando sea peligroso | Viajar Liviano |
| Utilizar las herramientas más sencillas | Asumir Simplicidad, tarjetas CRC |
