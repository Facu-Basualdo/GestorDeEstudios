# Historias de Usuario

> En XP, las historias de usuario son descripciones escritas por el cliente sobre lo que el sistema debe hacer, utilizadas para estimar tiempos y generar pruebas de aceptación.

Las historias de usuario sirven al mismo propósito que los casos de uso, pero no son la misma cosa. Son utilizadas para realizar estimaciones de tiempo para la planificación de entregas. Las historias de usuario son escritas por los clientes como cosas que el sistema debe hacer para ellos. Son escritas en formato de un texto en el lenguaje del usuario sin terminología técnica. Las historias de usuario también son utilizadas para generar las pruebas de aceptación. Una o más pruebas automáticas deben crearse para verificar que una historia de usuario ha sido implementada correctamente. Las historias de usuario deben tener un nivel de detalle apenas suficiente para realizar una estimación de cuanto tiempo durará su implementación. Cuando llega el momento de implementar la historia de usuario, los desarrolladores se juntan con el usuario y reciben información más detallada en una conversación cara-a-cara. Típicamente el tiempo necesario para la implementación de una historia de usuario varía de 1 a 3 semanas. Duraciones mayores a 3 semanas implican que debe particionarse la historia de usuario. Alrededor de 80 + o – 20 historias de usuario son suficientes para crear un plan de entregas razonable. En una historia de usuario deben evitarse detalles específicos acerca de tecnología, diseño de base de datos, algoritmos, etc. Las historias de usuario son escritas en tarjetas impresas o manualmente.
