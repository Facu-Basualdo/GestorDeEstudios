# Modelo de análisis

> Modelo del Proceso Unificado que describe el sistema desde una vista interna, con el lenguaje del desarrollador, y está estructurado por clases y paquetes estereotipados.

Es una vista interna del sistema, descrito con el lenguaje del desarrollador. Está estructurado por clases y paquetes estereotipados, proporcionando la estructura a la vista interna. Es utilizado fundamentalmente por los desarrolladores para comprender cómo debería darse forma al sistema, es decir, cómo debería ser diseñado e implementado. No debería contener redundancias, inconsistencias, etc., entre requisitos. Esboza cómo llevar a cabo la funcionalidad dentro del sistema, incluida la funcionalidad significativa para la arquitectura; sirve como una primera aproximación al diseño. Define realizaciones de casos de uso, cada una de las cuales representa el análisis de un caso de uso del modelo de casos de uso.

Es una jerarquía de paquetes del análisis que contienen clases del análisis y realizaciones de casos de uso.

Comparado con el modelo de diseño, el modelo de análisis es conceptual, genérico, con tres estereotipos sobre las clases (Control, Entidad e Interfaz), menos formal, menos caro (ratio al diseño 1:5), con menos capas, dinámico (no muy centrado en la secuencia), bosquejo del diseño, creado como "trabajo de a pie", puede no estar mantenido durante todo el ciclo de vida, y define una estructura que es una entrada esencial para el diseño.
