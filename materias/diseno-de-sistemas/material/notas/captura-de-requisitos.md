# Captura de requisitos

> La captura de requisitos es un paso previo, no muy formalizado en el PU, que busca identificar los requisitos que se deben desarrollar.

- Se puede considerar sinónimo de modelado de negocio.
- Se considera difícil porque el desarrollo de software es una disciplina socio-técnica y hay que saber lidiar con las personas, sobre todo en el contacto con clientes.
- En sistemas muy grandes los usuarios no reconocen todo lo que quieren; al tener una visión incompleta tampoco tienen un alcance global.
- En sistemas complejos las especificaciones de requisitos tienden a ser más largas.
- Los requisitos van a cambiar y hay que saber cómo lidiar con eso.
- Es la parte crucial: sacar lo que el usuario quiere de manera correcta.
- Las listas muy grandes de requisitos, si no están bien organizadas, pueden ser difíciles de leer.
- La mejor forma es tratar de capturar esos requisitos como casos de uso.
- A través de los casos de uso se busca concentrarse en las funcionalidades que aportan mayor valor para el usuario.
