# Communication among Stakeholders

> La arquitectura de software funciona como una abstracción común que los stakeholders de un sistema usan como base para el entendimiento mutuo, la negociación, el consenso y la comunicación.

La arquitectura es una abstracción del sistema que la mayoría de los stakeholders puede usar como base para crear entendimiento mutuo, negociar, formar consenso y comunicarse. Cada stakeholder se preocupa por características distintas del sistema que la arquitectura afecta: el usuario, por velocidad, confiabilidad y disponibilidad; el cliente, por cumplir el cronograma y el presupuesto; el manager, por que los equipos trabajen en forma independiente e interactúen de manera disciplinada y controlada; el arquitecto, por las estrategias para lograr todos esos objetivos. La arquitectura provee un lenguaje común en el que las distintas preocupaciones pueden expresarse, negociarse y resolverse a un nivel intelectualmente manejable, incluso para sistemas grandes y complejos. Sin ese lenguaje, es difícil entender sistemas grandes lo suficiente como para tomar las decisiones tempranas que influyen en la calidad y la utilidad. El análisis arquitectónico depende de este nivel de comunicación y lo realza.
