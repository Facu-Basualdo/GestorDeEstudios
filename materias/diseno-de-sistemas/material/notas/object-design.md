# Object Design

> Actividad de diseño orientado a objetos que, a partir de artefactos de análisis y con principios como GRASP, produce modelos y otros artefactos para explorar el diseño antes de codificar.

En un método iterativo, el diseño de objetos tiene entradas, actividades y salidas. Las entradas pueden incluir el taller de requerimientos, casos de uso seleccionados, especificación suplementaria, glosario, modelo de dominio, diagramas de secuencia del sistema y contratos de operación. Las ideas para la arquitectura lógica a gran escala, dibujadas con diagramas de paquetes UML, forman parte del UP Design Model. Las actividades incluyen empezar a codificar (idealmente con desarrollo *test-first*), hacer algún modelado UML (diagramas de interacción y de clases complementarios) u otra técnica como tarjetas CRC; durante el modelado se aplican principios de OOD como GRASP y los patrones GoF. Las salidas incluyen diagramas UML de interacción, clases y paquetes para las partes difíciles del diseño, bocetos y prototipos de UI, modelos de base de datos y bocetos de informes. Se modela principalmente para entender y comunicar, no para documentar.
